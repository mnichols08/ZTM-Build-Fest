# Kin v1.0 Compatibility and Upgrade Commitment

Kin keeps years of household records, so v1.0 makes a written promise about
what later releases will keep working. This document is that promise. It
freezes every persistent and wire format at its v1.0 version, says what v1.x
releases may and may not do to each, and says what happens to data from the
v0.x pre-releases.

A CI test (`scripts/v1-compatibility.test.mjs`) reads the frozen versions
below and compares them with the constants in the code. A pull request that
changes a frozen version fails CI unless it updates this document in the same
change.

## The promise for every v1.x release

For each format below, every v1.x release will:

1. **Read everything v1.0 wrote.** Data, exports and synced events made by
   v1.0 keep opening in every v1.x release.
2. **Migrate forward without loss.** When a v1.x release needs a newer local
   format, it upgrades the data in place, journalled so an interrupted upgrade
   resumes or rolls back. It never discards a household event: canonical
   event bytes are kept exactly as written.
3. **Never drop events silently.** An event a release can't apply is kept and
   reported (see the quarantine in [SYNC](SYNC.md)), never thrown away.
4. **Add, not replace.** New capabilities arrive as new event kinds, new
   optional fields or new protocol versions that older data doesn't need.
   Devices on different v1.x releases in one household keep syncing; a device
   that receives something newer than it understands pauses sync with an
   explanation instead of guessing.

What a v1.x release **may** do: add event kinds, raise the replay protocol to
add behaviour for new events, add IndexedDB stores or server tables with a
forward migration, and add new export package formats as long as it still
reads the v1.0 one.

## What only a major version (v2.0) may change

A major version may stop reading a v1.0 format, remove an event kind, or
change the meaning of existing events. If it does:

- the release notes and the app say so before anyone upgrades;
- the last v1.x release gains (or already has) an export that the new version
  reads, and the app asks people to export first;
- the threat model and this document are updated in the same release.

## Upgrading from v0.x

The v0.x releases were pre-releases, and their formats changed often. **v1.0
makes no compatibility promise for data created before v1.0.** Start fresh at
v1.0: create a new household and pair devices again. Kin may still open some
v0.x exports and local data, but that is not guaranteed, not tested as a
supported path, and may stop in any v1.x release.

The v1.0 promise above starts with the first data written by v1.0.
